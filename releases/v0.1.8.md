# v0.1.8 — clearer simplification decisions

## Changes

- Clarify failure ownership and recovery boundaries while preserving security, data integrity, and cleanup guarantees.
- Judge abstraction and change scope by shared contracts and required outcomes, including necessary changes across callers, types, tests, and documentation.
- Make preparatory refactoring, parallel migration, characterization tests, and bounded experiments conditional on the actual dependencies and risks.
- Distinguish compatibility obligations from behavior the user has authorized changing, so simplification preserves required behavior without freezing a requested bug fix.
- Add examples of unnecessary agent-generated machinery and a reference bibliography. Consolidate repeated entrypoint guidance and clarify English and Chinese documentation.

## 更新内容

- 明确失败归属和恢复边界，保留安全、数据完整性及资源清理保证。
- 按共享契约和完整需求判断抽象与修改范围，保留调用方、类型、测试和文档中的必要配套修改。
- 根据实际依赖与风险选择准备性重构、分步迁移、特征测试和有限试验，避免把方法变成必经流程。
- 区分兼容性义务与用户已授权改变的行为，防止“保留行为”阻碍修复已确认的错误。
- 补充智能体过度实现的例子和参考来源，合并入口中的重复指引，并改善中英文说明。
